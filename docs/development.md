# 개발 가이드

## 구현 판단

| 주제 | 선택 | 이유 |
|---|---|---|
| 서버 | Netlify Functions + Database + Identity | 이미 Netlify에 배포 중이라 새 서비스 계정이 필요 없고, 미리보기마다 DB 브랜치가 생깁니다. |
| 화면 구조 | 메인 → 리스트 → 디테일 | 메인은 차별점(국내 첫 공개)을 앞세우고, 리스트는 찾기에 집중하며, 디테일은 작품 정보와 재생 안내를 담습니다. 줄의 전체 보기, 장르, 감독, 배우 링크가 모두 리스트의 필터로 이어집니다. |
| 작품 정보 | 원제, 등급과 등급 사유, 러닝타임, 음성·자막, 분위기, 수입 이야기 | OTT 상세 화면에서 흔히 보는 항목에 이 서비스의 차별점인 수입 이야기와 국내 첫 공개 표시를 더했습니다. 장르는 TMDB 공식 목록에서 TV 영화만 뺐습니다. |
| 검색과 필터 | 서버에서 처리, 조건은 주소에 저장 | 작품이 늘어도 모두 내려받지 않습니다. 주소가 곧 상태라 공유, 새로고침, 뒤로 가기가 그대로 동작합니다. 화면과 서버가 `entities/movie/model/filters.ts`의 같은 규칙으로 값을 검증합니다. |
| 필터 적용 시점 | 적용 버튼 | 값을 바꾸는 것만으로 결과가 바뀌면 키보드와 스크린 리더 사용자가 고르는 중에 화면이 움직입니다. (KWCAG 7.2.1) |
| 연도·국가 목록 | `/api/movie-facets` | 실제 데이터에 있는 값만 보여 주어 결과가 비는 선택을 줄입니다. 감독과 배우는 수가 많아 `datalist`가 있는 입력으로 받고 일부만 입력해도 찾습니다. |
| 공개일 | 한국 날짜 기준 문자열 | Postgres `DATE`를 `Date`로 받으면 서버 시간대에 따라 하루가 밀리므로 `::text`로 받아 비교합니다. |
| 회원 | Netlify Identity | 비밀번호를 직접 저장하지 않습니다. 화면의 메뉴 숨김은 편의일 뿐이고 서버가 요청마다 확인합니다. 쿠키 인증이므로 상태를 바꾸는 요청은 `verifyRequestOrigin`으로 다른 사이트의 요청을 막습니다. |
| 결제 | 가상 결제, 카드 정보를 받지 않음 | 공개 사이트 방문자가 외부 키 없이 전체 흐름을 볼 수 있습니다. 성공과 실패를 골라 실패 처리까지 확인합니다. |
| 이용권 상태 | 읽을 때 정산(lazy settlement) | 예약 작업 없이 조회와 변경 직전에 지난 기간을 처리합니다. 기간 종료일을 조건에 넣어, 요청이 겹쳐도 한 기간은 한 번만 결제됩니다. |
| 중복 결제 방지 | 서버와 화면 양쪽 | 서버는 `ON CONFLICT ... WHERE status = 'expired'`로 구독과 결제 기록을 한 문장에서 처리합니다. 화면은 `isPending`이 바뀌기 전의 두 번째 클릭을 ref로 막습니다. |
| 이용권 변경 | 올리기는 즉시와 차액, 낮추기는 다음 결제일 | 이미 낸 기간의 혜택을 줄이지 않습니다. 차액은 일할 계산하지 않고 월 요금 차이로 단순화했습니다. |
| 재생 권한 | `watchBlock` 공유 | 디테일의 안내와 `/api/movies/:id/playback`이 같은 규칙을 씁니다. 안내는 편의이고 권한은 서버가 결정합니다. |
| 재생 화면 | 실제 영상 없음 | 프로젝트 범위를 화면과 권한으로 정했습니다. 자동 재생하지 않고 표준 버튼과 슬라이더만 씁니다. |
| 이어 보기 저장 | 재생 중 15초마다, 멈출 때 저장, 요청은 순서대로 | 위치가 바뀔 때마다 보내면 요청이 너무 많습니다. 저장이 겹치면 오래된 위치가 덮어쓸 수 있어 TanStack Query의 `scope`로 차례대로 보냅니다. 일시정지와 화면 이탈로 멈출 때 한 번 더 저장합니다. 러닝타임의 95%를 넘으면 끝까지 본 것으로 보고 뺍니다. |
| 찜·이어 보기 범위 | 로그인한 회원의 기록만 | 주소로 회원 ID를 받지 않고 항상 서버가 확인한 회원의 기록만 다룹니다. |
| 회원 탈퇴 순서 | 기록 삭제 → 계정 삭제 → 쿠키 삭제 | 계정을 먼저 지우면 기록 삭제가 실패했을 때 로그인할 수 없어 다시 시도할 길이 없습니다. 이 순서면 어느 단계에서 실패해도 다시 실행해 끝낼 수 있습니다. 로그인 쿠키는 계정을 지워도 만료될 때까지 유효하므로 서버에서 함께 지웁니다. |
| 보안 헤더 | `netlify.toml`, CSP 포함 | 스크립트는 사이트의 파일만 허용합니다. 테마 스크립트는 인라인 대신 `public/theme-init.js`로 두어 해시나 nonce 없이 처리합니다. 스타일은 Emotion의 주입 때문에 `'unsafe-inline'`을 허용합니다. `vite.config.ts`가 같은 CSP를 읽어 E2E에도 적용합니다. |
| 작품 정보 캐시 | `Netlify-CDN-Cache-Control` 60초, 이후 5분은 이전 응답을 주며 갱신 | 메인과 리스트가 함수와 DB를 깨우느라 1~3초 걸리던 대기를 줄입니다. 회원과 무관한 메인, 검색, 필터 목록, 작품 상세에만 붙이며 찜, 이어 보기, 재생 권한에는 붙이지 않습니다. 공개 상태 변경은 몇 분 늦을 수 있지만 재생 권한은 서버가 따로 확인합니다. |
| 요청 재시도 | 네트워크 오류와 5xx만 한 번 | 함수가 깨어나는 동안의 실패는 다시 시도하면 풀리지만, 4xx는 결과가 같아 안내만 늦어집니다. |
| 라우터 | TanStack Router, 코드 기반 경로(`src/app/router.tsx`) | 링크의 경로와 매개변수를 타입으로 확인합니다(`<Link {...routes.movie(id)}>`). 화면은 `getRouteApi('/movies/$id')`로 매개변수와 주소 조건을 읽어 앱 파일을 가져오지 않습니다(FSD). 주소 조건은 각 경로의 `validateSearch`가 검증하고, 값은 JSON 대신 평범한 쿼리로 둡니다(`shared/lib/routerSearch.ts`). 메인의 첫 JS는 React Router 때보다 gzip 약 5kB 작습니다(134.2kB → 128.9kB, 1회 측정). |
| 상태 메시지 | 처음부터 두는 `output`·`alert` 영역(`AlertMessage`), 화면 전체 실패는 레이아웃의 `PageAnnouncer` | 스크린 리더는 처음부터 있던 영역의 내용이 바뀔 때 읽습니다. 실패 안내로 초점을 옮기지 않고, 본문이 통째로 바뀌는 실패는 앱이 시작될 때부터 있는 영역으로 알립니다. |
| 요청 중 버튼 | `Button`의 `pending`(`aria-disabled`)과 `useRef` 잠금 | 초점을 가진 버튼을 `disabled`로 바꾸면 브라우저가 초점을 문서 처음으로 보내 키보드 사용자가 위치를 잃습니다. 빠른 두 번 누르기는 ref 잠금이 막습니다. |
| 아이콘 버튼 툴팁 | `Tooltip`(`role="tooltip"`), 글자를 `aria-labelledby`로 이름에 씀 | 마우스와 초점 모두에서 보이고 Esc로 닫힙니다. 툴팁 글자가 곧 버튼 이름이라 `aria-describedby`로 이으면 같은 말을 두 번 읽습니다. 화면 가장자리의 버튼은 안쪽으로 펼쳐 넘치지 않게 합니다. |
| 셀렉트 화살표 | `SelectControl`: `appearance: none`과 직접 그린 화살표 | 기본 화살표는 위치를 맞출 수 없어, 화살표가 오른쪽 끝에서 떨어진 거리를 왼쪽 글자 간격(테두리 1px + 여백 14px)과 같게 둡니다. |
| 동시 시청 제한 | 재생 중 30초마다 기기 자리 갱신, 70초 끊기면 해제 | 창을 닫아도 자리가 곧 풀립니다. 이미 재생 중인 기기는 끊지 않고 새 기기만 막으며, 두 기기가 같은 순간에 시작하면 한도를 잠시 넘을 수 있습니다. 네트워크 오류로는 재생을 멈추지 않습니다. |
| 공개 알림 | `/api/library/alert/:id`, 공개 후 확인 시 `read_at` | 메일을 보내지 않고 머리글의 종에서 확인합니다. 공개 여부는 조회 시점의 날짜로 판단해 예약 작업이 필요 없습니다. |
| 작품 이미지 | 장르별 장면을 `scripts/generate-seed.mjs`로 생성 | 작품 id로 난수를 정해 언제 만들어도 같은 그림이 됩니다. 시드 SQL은 내용이 같아 바뀌지 않습니다. |
| 이용권 색면 | `planSurfaceCss`가 색 변수를 다시 정의 | 안쪽의 버튼, 초점 표시, 오류 글자가 흰색 기준으로 바뀌어 색면 위에서도 대비가 유지됩니다. 어두운 이미지 위의 히어로도 같은 이유로 `--focus`를 흰색으로 둡니다. |
| 화면 오류 | 라우터 `defaultErrorComponent`와 `RouteErrorPage` | 라우터의 영문 기본 화면 대신 한국어로 안내합니다. 머리글을 유지해 다른 화면으로 갈 수 있습니다. 머리글까지 실패하면 최상위 경로의 `errorComponent`가 안내합니다. |
| 화면별 코드 분할 | 하지 않음 | 시험해 보니 메인의 첫 JS가 gzip 약 135.6kB에서 131kB로 3%쯤 줄 뿐이었습니다. 대부분이 React와 라우터 등 공통 코드라, 요청 단계가 하나 늘고 배포 뒤 예전 파일을 못 받는 경우까지 생기는 대가가 더 큽니다. |
| 스켈레톤 UI | 포스터는 `img` 배경, 목록은 카드 모양 | 포스터는 감싸는 요소 없이 `img` 자체에 그려 메인, 리스트, 디테일이 같은 컴포넌트(`MoviePoster`)를 씁니다. 스켈레톤은 스크린 리더에서 숨기고 안내는 `output`으로 한 번만 합니다. 필터를 바꿀 때는 이전 결과를 유지하므로 스켈레톤을 보여 주지 않습니다. |
| 로그인 뒤 이동 | `next`를 사이트 안 경로로 제한 | 다른 사이트로 보내는 공격을 막습니다. (`safeNext`) |
| SQL | `pg` 쿼리 직접 작성 | 쿼리가 많지 않고, Drizzle은 Netlify 어댑터가 베타 버전에만 있습니다. |
| 데이터 요청 | TanStack Query | 로딩·오류 상태와 저장 후 갱신을 한곳에서 처리합니다. 이용권은 회원 ID를 키에 넣어 로그아웃 뒤 다른 회원에게 보이지 않게 합니다. |
| 가로 목록 | CSS `grid-auto-columns`와 scroll snap | 화면 폭별 카드 수(2.3~8.3)를 CSS만으로 정합니다. 소수점만큼 다음 카드가 보여 옆으로 더 있음을 알립니다. 카드는 링크라 Tab으로 넘어가면 브라우저가 스크롤합니다. |
| 테마 | CSS 변수와 `data-theme` | `index.html`의 인라인 스크립트가 렌더링 전에 테마를 정해 깜빡임을 막습니다. |
| 린트 | oxlint | `typescript-eslint`가 TypeScript 7을 지원하지 않습니다. FSD 계층과 공개 API 규칙은 `no-restricted-imports`로 검사합니다. |
| esbuild 빌드 스크립트 | 실행하지 않음 (`pnpm-workspace.yaml`) | 없어도 빌드와 테스트가 동작합니다. 승인 여부를 정하지 않으면 `pnpm install`이 실패합니다. |
| 샘플 데이터 | 가상의 영화와 코드로 그린 SVG, 시드 마이그레이션 | 실제 영화 이미지의 저작권 문제를 피합니다. `scripts/generate-seed.mjs`와 원고 `scripts/seed-movies.mjs`로 만듭니다. |

### API 응답 검증

API 호출은 `src/shared/api/request.ts`를 거칩니다. 본문을 받는 요청은 `requestJson(path, schema)`로 zod 스키마(`entities/*/api/schemas.ts`)를 넘겨, 형식이 어긋난 응답을 화면을 그리기 전에 `InvalidResponseError`(502)로 바꿉니다. 스키마에는 서버와 함께 쓰는 타입을 붙여 두 정의가 어긋나면 타입 검사에서 드러납니다. 불러오기에 실패한 화면은 `shared/ui`의 `LoadFailed`(제목이 있는 경고)를 쓰고, 날짜는 `shared/lib/date.ts`의 `formatKoreanDate`로 표시합니다(잘못된 날짜는 `—`).

|---|---|---|
| 단위·컴포넌트 | `src/**/*.test.ts(x)` | 검색 조건 검증, 재생 권한, 필터, 가입·로그인, 가상 결제, 이용권 변경, 찜, 이어 보기, 탈퇴, 화면별 상태. API는 `shared/lib/test/fakeApi.ts`로 대신합니다. 화면은 `await renderWithProviders({ '/watch/$id': <WatchPage /> }, '/watch/a')`처럼 앱과 같은 경로 이름으로 그립니다. |
| 서버 | `netlify/lib/*.test.ts` | 실제 Postgres에 마이그레이션을 적용한 시드, 검색과 필터, 이용권 상태 변화(갱신, 만료, 올리기, 낮추기, 중복 요청), 찜과 이어 보기, 탈퇴 시 기록 삭제 |

| 배포 검사 | `e2e/live.spec.ts` | 배포된 사이트의 3단 흐름, 이미지, axe, 보안 헤더, 회원 응답이 캐시되지 않음, 비로그인·다른 사이트의 요청 거부. 운영 데이터를 바꾸지 않습니다. |

```bash
pnpm exec playwright install chromium firefox webkit  # 처음 한 번
pnpm build
pnpm test:e2e
```

E2E는 기본으로 포트 4310을 쓰며, `E2E_PORT`로 바꿀 수 있습니다.

CI는 `main` 푸시와 PR마다 타입 검사, 린트, 포맷 검사, 단위 테스트, 빌드, E2E를 실행합니다.

## 성능

- 로그인 코드는 로그인, 가입, 로그아웃 때만 받습니다.
- **번들 크기:** `pnpm size`가 첫 화면 JS 150 kB, CSS 53 kB(gzip)를 넘으면 실패합니다. 기준은 `.size-limit.json`에 있습니다.
- **Lighthouse:** `pnpm lhci`가 `scripts/lighthouse-server.ts`로 `dist/`를 띄우고 첫 화면·영화 목록·영화 상세를 데스크톱 기준 3번씩 재서 성능 90·접근성 100·권장 사항 95·SEO 90점, LCP 2.5초·TBT 200ms·CLS 0.1 이하인지 확인합니다. `vite preview`에는 Netlify 함수가 없어, 이 서버가 E2E와 같은 목업 데이터(`e2e/fakeData.ts`)로 `/api/*` 읽기 요청에 답합니다. 2026-11-12 측정은 첫 화면 94~95, 목록 95~96, 상세 96점(접근성·권장 사항·SEO 100)입니다.

## 모니터링

`src/app/main.tsx`가 화면을 그리기 전에 `app/monitoring`을 켜고, Sentry와 web-vitals는 나중에 따로 받습니다. Sentry는 페이지를 다 받은 뒤(load) 브라우저가 한가할 때 받고, load가 10초 안에 오지 않으면 그때 바로 받습니다.

| 환경 변수 | 내용 |
| --- | --- |
| `VITE_SENTRY_DSN` | 있으면 처리하지 못한 오류와 나쁜(poor) Web Vitals를 Sentry로 보냅니다. 없으면 Sentry를 번들에 넣지 않고, 개발 모드에서 Web Vitals를 콘솔에만 찍습니다 |

- TanStack Router가 잡아 오류 화면으로 바꾼 오류는 전역으로 올라가지 않으므로 `defaultOnCatch`에서 `reportError`로 보냅니다.
- Sentry에는 주소의 `#` 뒤(로그인·복구 토큰이 실릴 수 있음), 오류에 붙는 콜백 인수, Error가 아닌 일반 객체로 거부된 Promise의 필드 값(`extra.__serialized__`)을 보내지 않습니다.
- Sentry에는 오류 내용만 보내고 사용자 정보·쿠키·헤더·쿼리 문자열, 방문 기록(세션), 이동·클릭 기록(브레드크럼), 콘솔 기록은 모으지 않습니다. Sentry를 받기 전에 난 오류는 최대 20개까지 모아 두었다가 처리되지 않은 오류로 보냅니다.
- 쓰는 함수만 `sentry.ts`에서 다시 내보내 약 31 kB(gzip)로 받습니다. 모듈 전체를 불러오면 리플레이·피드백까지 들어가 140 kB가 됩니다.
- Netlify Functions(서버)의 오류는 Netlify 로그로 확인합니다.

## 배포 전 설정

Identity는 API가 없어 대시보드에서만 설정합니다. 처음 한 번 순서대로 합니다.

1. **Netlify Database:** `@netlify/database`가 있으면 첫 배포 때 만들어지고 마이그레이션이 적용됩니다. 크레딧 기반 요금제에서만 쓸 수 있고 사용량에 따라 크레딧을 씁니다.
2. **Identity 켜기:** Project configuration의 Identity(`https://app.netlify.com/projects/<사이트 이름>/identity`)에서 켭니다.
3. **가입 열기:** Registration을 **Open**으로 둡니다. 2.x에서 **Invite only**로 바꿨다면 되돌려야 회원가입이 동작합니다.
4. **가입 확인:** 운영은 **Autoconfirm을 끈 채**로 둡니다. 확인 메일의 링크를 눌러야 가입이 끝나고, 링크는 사이트 첫 화면으로 와서 `/login`에서 처리합니다. 메일은 Netlify 기본 발신 주소로 갑니다.

## 로컬 개발

- `pnpm dev`가 `@netlify/vite-plugin`으로 함수와 DB를 흉내 냅니다. DB 파일은 `.netlify/db`에 있습니다.
- 마이그레이션은 자동으로 적용되지 않습니다. `pnpm dev`를 켠 채로 `pnpm db:migrate`를 실행합니다.
- Identity는 로컬에서 동작하지 않아, 로컬 함수에서는 가상의 회원으로 간주합니다(`netlify/lib/auth.ts`). 배포된 함수에는 해당하지 않습니다. 가입과 로그인 흐름은 운영 배포 뒤 배포 검사와 직접 확인으로 봅니다. PR 단계에서 확인해야 하면 `scripts/netlify-ignore.sh`의 미리보기 건너뛰기를 잠시 풀어 둡니다.
- 엣지 함수 에뮬레이터는 끕니다(`vite.config.ts`). 이 프로젝트는 엣지 함수를 쓰지 않고, 켜 두면 Deno 버전에 따라 개발 서버가 종료됩니다.
- 시작할 때 `Failed retrieving site data`가 나면 상위 폴더의 `.netlify/state.json`이 다른 사이트를 가리키는 경우입니다. `netlify link`로 이 프로젝트를 연결하거나, 이 폴더에 `.netlify/state.json`을 `{}`로 만듭니다.

## 배포 시 유의점

- `main`에 병합하면 Netlify가 `netlify.toml` 설정으로 빌드하고 **마이그레이션을 적용한 뒤** 배포합니다. 이어서 `.github/workflows/live-check.yml`이 `version.txt`로 해당 커밋의 배포를 확인한 뒤, 세 브라우저로 배포된 사이트를 검사합니다.
- Netlify 팀 크레딧을 아끼려고 빌드를 줄입니다(`scripts/netlify-ignore.sh`, `netlify.toml`의 `ignore`). PR 미리보기와 브랜치 배포는 빌드하지 않고, `main`도 문서·E2E·테스트·저장소 설정(`docs/`, `e2e/`, `.github/`, `README.md`, `CHANGELOG.md`, `*.test.ts(x)`)만 바뀐 커밋은 건너뜁니다. 이때는 배포 검사도 돌지 않습니다(`paths-ignore`, 같은 목록). 배포 검사를 손으로 돌렸을 때 배포된 커밋 이후로 이런 변경만 있었다면, 같은 스크립트로 확인해 배포된 사이트를 그대로 검사합니다. PR의 빌드와 E2E 검사는 GitHub Actions가 맡습니다.
- 크레딧을 다 쓰면 팀이 operational credits 상태가 되어 사이트는 그대로 열리지만 새 배포가 멈춥니다. 배포 검사가 "10분 안에 배포되지 않았습니다"로 실패하면 Netlify의 Usage 화면부터 확인합니다.
- 적용된 마이그레이션은 고치거나 지우면 배포가 실패합니다. 항상 새 파일을 추가합니다.
- 미리보기를 다시 켜면(위의 빌드 건너뛰기를 풀면) 운영 데이터가 복사된 DB 브랜치를 쓰고, 미리보기 주소는 공개입니다.
- 직접 주소는 SPA 대체 규칙으로 HTTP 200을 돌려줍니다. 없는 주소는 앱의 404 화면이 열리지만 HTTP 상태는 200입니다.
- 없는 `/assets/*`는 앱 화면이 아니라 404로 응답합니다. `robots.txt`처럼 고정 주소로 읽는 파일은 `public/`에 두어야 대체 규칙에 걸리지 않습니다.
- 공유 미리보기 정보는 `index.html` 하나뿐이어서 어느 주소를 공유해도 메인 기준으로 보입니다.
- `og:image`와 `og:url`은 배포 주소를 절대 경로로 씁니다. 주소가 바뀌면 `index.html`도 고칩니다.

## 알려진 제한

- 재생 화면에 실제 영상이 없습니다. 시간만 흐르고 자막과 음소거는 화면 상태입니다. 일시정지 상태에서 옮긴 위치는 다시 재생해야 저장됩니다.
- 성인 인증이 없어 청소년 관람불가 작품은 넣지 않았습니다. 스키마와 등급 표시는 지원합니다.
- 두 기기가 같은 순간에 재생을 시작하면 동시 시청 한도를 잠시 넘을 수 있습니다.
- 공개 예정작의 공개일은 시드에 고정되어 있어(2027년 1~4월) 그날이 지나면 공개 중으로 넘어갑니다. E2E는 날짜를 고정해 영향을 받지 않습니다.
- 가입, 로그인, 메일 확인은 배포 환경에서만 끝까지 동작합니다. 자동 테스트는 Identity를 대신해 검사합니다.
- 가입에 실제 메일 확인이 필요합니다. 배포 검사(`live.spec.ts`)는 메일함을 열 수 없어 운영 계정을 만들지 않으므로, 실제 가입부터 재생까지는 사람이 확인합니다.
- Netlify가 페이지에 넣는 인라인 프레임 스크립트(운영의 Powered by Netlify 배지, Deploy Preview의 검토 도구)는 CSP에 막혀 뜨지 않고 콘솔 오류를 남깁니다. 사이트 기능에는 영향이 없습니다. 무료 플랜에서는 배지를 끌 수 없어(설정이 Upgrade to unlock으로 잠겨 있음) 배포 검사가 배지 오류만 제외합니다. Deploy Preview의 검토 도구 오류는 제외하지 않으므로 `LIVE_URL`로 미리보기를 검사하면 3단 흐름 검사가 실패합니다.
- 관리자 화면이 없습니다. 영화는 시드 마이그레이션으로만 추가합니다.
- 탈퇴가 계정 삭제 단계에서 실패하면 이용권과 기록은 이미 지워진 상태로 계정만 남습니다. 다시 시도하면 끝납니다.
- 다른 기기의 로그인 쿠키는 탈퇴 뒤에도 만료될 때까지 유효해, 그 기기에서 보내는 요청이나 탈퇴 도중 처리되던 요청이 찜이나 재생 위치를 다시 만들 수 있습니다. 남는 값은 회원 ID와 영화 ID, 재생 위치뿐이며, 요청 간 잠금을 두지 않았습니다.
- 찜과 이어 보기 목록의 상한 제거를 검사하는 테스트는 시드 36편으로 돌립니다. 작품이 50편을 넘으면 테스트도 늘려야 합니다.
